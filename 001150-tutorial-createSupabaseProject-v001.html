72  72. Step 5: Setup Supabase

Supabase is an online service that gives you the tools you need to store and manage data for your app. It includes:

  • a database (where structured data is stored)
  • authentication features (to allow users to sign-in to your app)
  • file storage (like a hard drive in the cloud)
  • “edge functions,” which are small pieces of code that run on servers close to your users.

72.1 Remote vs. Local Supabase

Supabase can run remotely (hosted online by Supabase) and/or locally (running on your own computer). For beginners, remote Supabase is far easier. Everything happens in your browser, and nothing must be installed or configured. Local Supabase is mainly for advanced users and developers who want to test everything on their own computer before uploading to the Internet. Having a local copy of supabase also allows you to develop your app during times that you don’t have access to the Internet.

In this tutorial we will use remote Supabase only, so you do not need to install a local copy or manage anything technical on your machine.

72.2 Sign Up for Supabase

  1. Go to the Supabase website
  2. Sign up for a free account
  3. Create a new project

72.3 Project Configuration

When creating your project, you’ll need to:

  • Choose a project name
  • Set a database password (save this securely)
  • Select a region (choose the closest to your users)

Important: Save your database password - you’ll need it later.

72.4 Get Your API Keys

Once your project is created:

  1. Edit the .env.local file. It currently looks like this:
# You will need a .env.local file for local dev server (localhost)
# You will need a .env.test.local file for running the integration tests.

# Create the those files, and add the following variables.
# The local files are ignored by default.

# In .env.local and .env.test.local:
NEXT_PUBLIC_SUPABASE_URL="https://XXXX.supabase.co"
NEXT_PUBLIC_SUPABASE_ANON_KEY="XXXX"

# In addition to that, you also need .env.test.local with these variables:
SUPABASE_SERVICE_KEY="XXXX"
STRIPE_SECRET_KEY="sk_test_XXX"
STRIPE_PRICE_ID="price_XXX"
STRIPE_WEBHOOK_SECRET="whsec_XXX"```

  1. Delete the bottom few lines and top few lines so that the file now looks like this:

    # In .env.local and .env.test.local:
NEXT_PUBLIC_SUPABASE_URL="https://XXXX.supabase.co"
NEXT_PUBLIC_SUPABASE_ANON_KEY="XXXX"

  2. Go to Project Settings (Gear button at bottom left of screen) → Data API

    Copy the URL.
    Modify the following line in the .env.local file to reflect the URL that you copied.

    NEXT_PUBLIC_SUPABASE_URL="https://XXXX.supabase.co"

  3. Click on the API Keys section.
    Copy the anon public key.

    Modify the following line in the .env.local file to reflect the URL that you copied.

    NEXT_PUBLIC_SUPABASE_ANON_KEY="XXXX"

Practice Questions

Easy

Question 1 · Multiple choice

Which of the following is not one of the Supabase features listed on this page?

  1. A database for storing structured data
  2. Authentication, so users can sign in to your app
  3. File storage in the cloud
  4. Processing credit card payments
Suggested answer

d. Supabase gives you a database, authentication, file storage and edge functions. Payments are not a Supabase feature; in this project they are handled by a separate service, Stripe. Options a, b and c are all on the page’s list.

Question 2 · Short answer

What are Supabase edge functions?

Suggested answer

Small pieces of code that run on servers close to your users (on Supabase’s servers, not in the user’s browser). In task-app, edge functions do jobs such as asking the OpenAI API to pick a tag for a task and talking to Stripe.

Question 3 · True or false

In this tutorial, you install and run your own copy of the Supabase server on your computer.

Suggested answer

False. The tutorial uses remote Supabase only: Supabase runs the server online, and you set it up through your browser. Running Supabase locally is mainly for advanced developers.

Question 4 · Short answer

When you create a new Supabase project, which three things does this page say you need to choose or set?

Suggested answer
  1. A project name.
  2. A database password (save it somewhere safe; you’ll need it later).
  3. A region (choose the one closest to your users).

Medium

Question 5 · Multiple choice

Most of your app’s users will be in New York. Which region should you pick for your Supabase project?

  1. The region closest to you, the developer
  2. The region closest to your users, such as an East US region
  3. Any region; the choice makes no difference
  4. Whichever region is listed first in the menu
Suggested answer

b. The page says to choose the region closest to your users. Data that travels a shorter distance arrives faster, so the app responds more quickly. Where you, the developer, are located (a) matters less than where your users are, and the region does make a difference (c). The order of the menu (d) means nothing.

Question 6 · Short answer

Give two reasons why a developer might run Supabase locally (on their own computer) instead of using only the remote version.

Suggested answer
  1. To test everything on their own computer before uploading it to the Internet.
  2. To keep working on the app when they don’t have Internet access.

The price is that local Supabase must be installed and configured, which is why this tutorial uses remote Supabase.

Question 7 · Fill in the blank

Your Supabase project URL is https://qzvbnmtrewplkjhgfdsa.supabase.co. Write the complete line in .env.local that stores it.

Suggested answer 
NEXT_PUBLIC_SUPABASE_URL="https://qzvbnmtrewplkjhgfdsa.supabase.co"

Keep the variable name and the quotes exactly as they are, and replace the whole placeholder https://XXXX.supabase.co with your real URL.

Question 8 · Short answer

The original file also contains SUPABASE_SERVICE_KEY, STRIPE_SECRET_KEY, STRIPE_PRICE_ID and STRIPE_WEBHOOK_SECRET. According to the comments in the file, why can you delete those lines from .env.local?

Suggested answer

.env.local is used by the local development server, which only needs the two NEXT_PUBLIC_SUPABASE_... lines. The other variables are only needed in a separate file, .env.test.local, which is used for running the project’s integration tests.

Question 9 · True or false

Even though your project is a Git repository, it is OK to type your real Supabase values into .env.local.

Suggested answer

True. As the comment in the file says, the “local” env files are ignored by default: the project’s .gitignore file lists them, so Git never commits them. That is exactly why real values go into .env.local and not into .env.example, which is committed. Still, treat the file as private.

Hard

Question 10 · Scenario

Sam starts the app, but nothing that needs Supabase works. His .env.local contains:

NEXT_PUBLIC_SUPABASE_URL="https://XXXX.supabase.co"
NEXT_PUBLIC_SUPABASE_ANON_KEY="XXXX"

What went wrong, and how does he fix it?

Suggested answer

He never replaced the placeholders that came from the example file, so the app is trying to reach a Supabase project that doesn’t exist. He needs to copy his own project’s URL and key from his Supabase dashboard into these two lines and save the file. Restarting the development server (npm run dev) makes sure the app picks up the new values.

Question 11 · Short answer

The page tells you to save your database password securely. Why is this password so important? Give two reasons.

Suggested answer
  1. You’ll need it later in the tutorial, so you must be able to find it again.
  2. It is the password to your project’s database. Anyone who has it could connect to the database directly and read or change all of your app’s data, so treat it like any other important password: keep it out of Git and don’t share it.

Question 12 · True or false

Two classmates clone the same task-app repository from GitHub. Because the Supabase project URL is stored in the repository, both copies of the app automatically use the same Supabase project.

Suggested answer

False. The repository only contains .env.example, with placeholders such as https://XXXX.supabase.co. Each student creates their own Supabase project and puts its URL in their own .env.local. That file is ignored by Git, so it never goes into the repository, and each copy of the app talks to its own project.
