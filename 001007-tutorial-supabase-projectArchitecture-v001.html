66.3 Keeping notes - Setup checklist

Over the course of this tutorial we will have to address all of the following in order to setup this project to work. The following sections will go into more detail about each of these topics:

Many of these steps require keeping track of numerous URLs, “keys” and other “configuration information” for your project. Often the “configuration information” is generated on one website (e.g. vercel, supabase, google cloud console, stripe) and must be copied to a different website or recorded in a specific file on your computer.

Keeping track of all this information can get VERY confusing. If you’re doing this kind of thing for the first time, it could help a lot to have one place (e.g. a Word document) that you use to keep notes and record all the configuration information you will need. This makes it much easier to review your setup and debug it when there are problems. In addition to the keys, urls, etc, it can be helpful to paste screenshots into this Word document to help you remember where you retrieved the info from and where you copied it to.

Keep in mind that much of this configuration information should be treated as “secret info” similar to your passwords. Therefore, treat this Word document as you would treat your passwords.

Practice Questions

Easy

Question 1 · Multiple choice

In this project, which code runs in the user’s browser?

  1. The PostgreSQL database
  2. The client-side part of the Next.js web app (HTML, CSS and JavaScript), including the Supabase client library
  3. The Supabase edge functions
  4. Stripe’s payment processing
Suggested answer

b. The frontend is the code that runs in the browser: the client-side portion of the Next.js app, plus the client library it uses to talk to Supabase. The database (a) and the edge functions (c) run on Supabase’s servers, and Stripe (d) runs on Stripe’s own servers.

Question 2 · Matching

Match each part of the architecture with its job.

Part Job
1. Vercel A. stores the app’s data
2. Supabase PostgreSQL database B. stores the uploaded image files (similar to Amazon S3)
3. Supabase storage C. the web server that runs the server side of the Next.js app
4. Supabase edge functions D. lets users log in with their Google account
5. Google Cloud (OAuth) E. processes payments
6. OpenAI API F. TypeScript functions that run on Supabase’s servers
7. Stripe G. uses AI to pick a “tag” for each task
Suggested answer

1 → C, 2 → A, 3 → B, 4 → F, 5 → D, 6 → G, 7 → E.

Question 3 · True or false

In this project, Vercel stores the image files that users attach to their tasks.

Suggested answer

False. Image files go into Supabase’s storage system (similar to Amazon S3). Vercel is the web server that hosts the Next.js app.

Question 4 · Fill in the blank

Supabase edge functions are written in ______ and run on ______’s servers, using the ______ runtime environment instead of Node.js.

Suggested answer

TypeScript; Supabase; Deno.

Question 5 · Short answer

What is a “tech stack”? Name the main technologies in this project’s tech stack.

Suggested answer

A tech stack is the set of technologies an app is built from (languages, frameworks and services), together with where each part runs. This project’s tech stack:

  • Next.js, running partly in the browser and partly on Vercel’s web server
  • Supabase: PostgreSQL database, storage, authentication and edge functions
  • third-party services: Google OAuth, the OpenAI API and Stripe

Medium

Question 6 · Ordering

Put the setup checklist in the order the page gives:

  • Deploy edge functions
  • Set up Stripe
  • Clone the project from GitHub
  • Test the application
  • Create Supabase project
  • Configure OpenAI API
  • Set up Google OAuth
Suggested answer
  1. Clone the project from GitHub
  2. Create Supabase project
  3. Set up Google OAuth
  4. Configure OpenAI API
  5. Set up Stripe
  6. Deploy edge functions

The logic: you need the code first; the Supabase project has to exist before other services can be connected to it; the edge functions use the OpenAI and Stripe keys, so they are deployed after those services are set up; and testing comes last, when everything is connected.

Question 7 · Short answer

Look at the architecture diagram. Which part of Supabase connects to Google OAuth, and which part connects to the OpenAI API and Stripe?

Suggested answer

Authentication connects to Google OAuth: Supabase’s login system lets users sign in with their Google account. Edge functions connect to the OpenAI API and Stripe: they are server-side code, so they can safely use those services’ secret keys.

Question 8 · Short answer

Why does the page recommend keeping one notes document (for example, a Word document) while you set up this project, and what should you put in it?

Suggested answer

Setup produces many URLs, keys and other configuration values. A value is often created on one website (Vercel, Supabase, Google Cloud console, Stripe) and must be copied to another website or into a specific file on your computer. Keeping everything in one place makes it much easier to review your setup and to debug problems.

Put in the keys, URLs and other configuration information, plus screenshots that show where you got each item and where you copied it to.

Question 9 · Multiple choice

Your setup notes document contains API keys and other configuration values. How should you treat it?

  1. Commit it to your GitHub repository so you never lose it
  2. Like your passwords: keep it private and don’t share it
  3. Paste it into the project’s README so teammates can find it
  4. Share it freely - configuration values are never secret
Suggested answer

b. Much of this information is secret, just like a password: anyone who has your secret keys could use your accounts. Options (a) and (c) would publish the secrets to everyone who can see the repository, and (d) is simply not true.

Question 10 · True or false

Supabase had no choice but to use Deno for its edge functions, because Node.js could not have been used for this.

Suggested answer

False. The page says that, in theory, Supabase could have used Node.js. Deno is often chosen as a runtime environment for TypeScript. Both Deno and Node.js are runtime environments: programs that run JavaScript code outside a browser.

Hard

Question 11 · Scenario

For each problem below, which part(s) of the architecture would you investigate first?

  1. “Log in with Google” fails.
  2. Tasks save correctly, but attaching an image to a task fails.
  3. New tasks are saved but never get an AI tag.
  4. The page for upgrading to a paid subscription doesn’t work.
Suggested answer
  1. Supabase authentication and the Google OAuth setup in Google Cloud.
  2. Supabase storage.
  3. The edge functions and the OpenAI API (for example, a missing or wrong API key).
  4. Stripe and the edge functions that work with it.

The diagram tells you which pieces work together for each feature, so you know where to start looking; your setup notes tell you which keys and URLs you entered where.

Question 12 · Long answer

Explain the difference between the frontend and the backend in this project. Why is the backend spread across several companies’ servers (Vercel, Supabase, Google, OpenAI, Stripe) instead of running on one computer?

Suggested answer

The frontend is the client-side part of the Next.js app (HTML, CSS, JavaScript) running in the user’s browser: what the user sees and clicks. The backend is everything that runs on servers: Vercel runs the server-side part of the Next.js app; Supabase runs the PostgreSQL database, file storage, authentication and edge functions; and Google, OpenAI and Stripe provide login, AI and payments.

The backend is spread out because each company specializes in one hard job. Instead of building your own login system, payment processing or AI model, you use theirs and connect them with keys and URLs. The trade-off is more accounts, keys and settings to manage - which is why setup is the hard part, and why the page recommends keeping careful notes.

Question 13 · Short answer

The diagram shows Next.js in two places: in the browser and on Vercel’s web server. Why?

Suggested answer

A Next.js web app has two portions. The client-side portion (HTML, CSS and JavaScript) is sent to the user’s browser and runs there. The server-side portion is JavaScript that runs in Node.js on the web server (Vercel). One Next.js project produces the code for both places.
