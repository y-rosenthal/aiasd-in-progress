21  21. Wildcards, Pipes, and Searching

This page covers three things that make the command line powerful: wildcards (work with many files at once), pipes (connect commands to each other), and search commands (find files, and find text inside files). The examples use the practice files from Files, Folders, and Paths.

21.1 Wildcards: matching many file names

A wildcard is a special character that stands for other characters in a file name. A name pattern that contains wildcards is often called a glob.

Wildcard Matches Example Matches in the practice files
* any number of characters (even none) music/*.mp3 song1.mp3, song2.mp3
? exactly one character music/song?.mp3 song1.mp3, song2.mp3
[abc] exactly one of the listed characters pictures/[fg]* family.jpg (names starting with f or g)

echo shows what a wildcard matches:

cd ~/Documents/bash-tutorial-files
echo music/*.mp3
echo music/*1*
echo documents/reports/*.txt

Output:

music/song1.mp3 music/song2.mp3
music/song1.mp3
documents/reports/annual-summary.txt documents/reports/quarterly-report.txt

Wildcards work with every command. Remember the example from What Is the Command Line?: moving every file with 2025 in its name takes one command. Try it with two new folders:

mkdir project1 project2
touch project1/budget-2025.xlsx project1/budget-2026.xlsx project1/sales-2025.docx
mv project1/*2025* project2
ls project2

Output:

budget-2025.xlsx  sales-2025.docx

21.1.1 The shell expands wildcards, not the command

The shell replaces a wildcard pattern with the list of matching names before it runs the command. When you type ls *.txt, ls never sees the *; it receives the file names. That’s why echo is a safe way to preview what a pattern will match.

When nothing matches, for example ls *.pdf in a folder without PDF files, the Mac and Git Bash behave differently:

  • Mac
  • Windows (Git Bash)

zsh stops with an error and doesn’t run the command at all:

zsh: no matches found: *.pdf

(This also happens if you paste a web address containing ? without quotes. Put quotes around addresses.)

Bash passes the pattern unchanged, so ls looks for a file literally named *.pdf:

ls: cannot access '*.pdf': No such file or directory

Two more details:

  • Quotes turn wildcards off. echo "*.txt" prints *.txt. You need this when you want to hand the pattern itself to a command, as with find below.
  • * doesn’t match hidden files, whose names start with a dot.
Preview before you delete

rm *.tmp deletes every matching file instantly, with no Trash. Run ls *.tmp first to see exactly what matches. Watch out for stray spaces: rm * .tmp means “delete everything, and also a file named .tmp.” (zsh on a Mac asks “sure you want to delete all … files?” before running a command like that; Bash does not ask.)

21.2 Pipes: connecting commands

A pipe, the | character, sends the output of one command into the next command as its input, like an assembly line:

Pipeline What it does
ls -l | less shows a long file listing one screen at a time
history | grep cd shows only the past commands that contain cd
cat data.csv | wc -l counts the lines in data.csv

Compare pipes with redirection: > sends output into a file, while | sends it into another command.

21.3 Searching inside files: grep

grep prints the lines of a file that contain a word or phrase. First, give the notes some content (this replaces what you wrote on earlier pages):

cd ~/Documents/bash-tutorial-files/documents/notes
echo "Budget review on Monday" > meeting-notes.txt
echo "Action: Maria updates the budget" >> meeting-notes.txt
echo "Action: Sam books the room" >> meeting-notes.txt
echo "Idea: a budget tracker app" > ideas.txt
grep budget meeting-notes.txt

Output:

Action: Maria updates the budget

grep is case-sensitive, so it skipped Budget. These options change that and more:

Option Meaning Example
-i ignore upper/lower case grep -i budget meeting-notes.txt
-n show line numbers grep -n Action meeting-notes.txt
-r search all files in a folder and its subfolders grep -r budget . 
grep -i budget meeting-notes.txt
grep -n Action meeting-notes.txt

Output:

Budget review on Monday
Action: Maria updates the budget
2:Action: Maria updates the budget
3:Action: Sam books the room

When grep searches several files, it puts the file name in front of each match. Options can be combined. From the documents folder:

cd ..
grep -r -i -n budget .

Output (the files may be listed in a different order):

./notes/meeting-notes.txt:1:Budget review on Monday
./notes/meeting-notes.txt:2:Action: Maria updates the budget
./notes/ideas.txt:1:Idea: a budget tracker app

Always tell grep -r which folder to search (. means the current folder). If grep finds nothing, it prints nothing.

21.4 Finding files by name: find

find searches a folder and all of its subfolders for names that match a pattern. From bash-tutorial-files:

cd ~/Documents/bash-tutorial-files
find . -name "*.css"

Output:

./projects/website/styles.css

The . means “start searching here”. Put the pattern in quotes so the shell passes it to find unchanged instead of expanding it first. find matches folder names too; add -type f to list only files:

find . -name "*report*"
find . -name "*report*" -type f

Output:

./documents/reports
./documents/reports/quarterly-report.txt
./documents/reports/quarterly-report.txt

The first command found the folder reports and the file inside it; the second found only the file. (Use -iname instead of -name to ignore upper/lower case.)

21.5 Counting and sorting: wc, sort, head, tail

Create a small data file:

cd ~/Documents/bash-tutorial-files/projects/data-analysis
echo "East,500" > data.csv
echo "West,750" >> data.csv
echo "North,320" >> data.csv
echo "South,610" >> data.csv
echo "East,410" >> data.csv
Command What it does
wc -l data.csv counts the lines (wc = “word count”; without -l it also counts words and characters)
sort data.csv prints the lines in alphabetical order (-r reverses, -n sorts numbers by value)
head -n 3, tail -n 3 the first / last lines (see Writing to Files) 
wc -l data.csv
sort data.csv

Output:

5 data.csv
East,410
East,500
North,320
South,610
West,750

(On a Mac, wc puts some spaces in front of the number.)

These small commands become powerful in pipelines. How many rows are for the East region? Which two rows come first alphabetically?

grep East data.csv | wc -l
sort data.csv | head -n 2

Output:

2
East,410
East,500

21.6 Saving results to a file

Pipes and searches combine with redirection (>) from Writing to Files, so you can keep the results:

cd ~/Documents/bash-tutorial-files/documents/notes
grep -n Action meeting-notes.txt > action-items.txt
cat action-items.txt

Output:

2:Action: Maria updates the budget
3:Action: Sam books the room

Other examples: find . -name "*.jpg" > photo-list.txt saves a list of photos, and history | grep git > git-commands.txt saves your past Git commands.

21.7 How Claude Code searches your files

As of Oct 6, 2026 · Official docs: Tools reference

When Claude Code needs to find something in your project, it uses exactly these ideas. On a Mac (and on Linux), it searches by running find and grep commands through its Bash tool (using its own built-in versions of these programs), so commands like the ones on this page are literally what you’ll see it run. On Windows, it has two built-in tools for this instead: Glob, which finds files whose names match a wildcard pattern such as **/*.js (all .js files in any subfolder), and Grep, which searches inside files. You’ll meet Claude Code’s tools in How Claude Code Works.

Practice Questions

Easy

Question 1 · Multiple choice

Which file names does the pattern *.csv match?

  1. Only a file literally named *.csv
  2. Every name that ends in .csv
  3. Every name that contains exactly one character before .csv
  4. Every file in the folder
Suggested answer

b. * matches any number of characters, so *.csv matches data.csv, sales-2026.csv, and so on. Option a is what happens when the pattern is in quotes ("*.csv"), c describes ?.csv, and d describes * on its own.

Question 2 · Short answer

What does the wildcard ? match? Give an example.

Suggested answer

Exactly one character. For example, song?.mp3 matches song1.mp3 and song2.mp3, but not song10.mp3 (two characters) or song.mp3 (none).

Question 3 · True or false

When you type ls *.txt, the ls command itself searches the folder for names that match *.txt.

Suggested answer

False. The shell expands *.txt into the list of matching file names before running ls. ls only receives the names; it never sees the *.

Question 4 · Short answer

What does the pipe character | do in history | grep cd?

Suggested answer

It sends the output of the first command (history, the list of past commands) into the second command (grep cd) as its input. The result shows only the past commands that contain cd.

Question 5 · Matching

Match each command or option with its meaning.

Command or option Meaning
1. grep -i A. search all files in a folder and its subfolders
2. grep -n B. find files whose names match a pattern
3. grep -r C. ignore upper/lower case
4. find . -name D. show line numbers
Suggested answer

1 → C, 2 → D, 3 → A, 4 → B.

Question 6 · Short answer

What does wc -l report.txt tell you?

Suggested answer

The number of lines in report.txt (followed by the file name).

Medium

Question 7 · Write the command

Write a command that lists only the .csv files in the current folder.

Suggested answer 
ls *.csv

Question 8 · Predict the output

In bash-tutorial-files, what do these commands print?

echo pictures/*.jpg
echo music/song?.mp3
echo "music/*.mp3"
Suggested answer 
pictures/family.jpg pictures/vacation.jpg
music/song1.mp3 music/song2.mp3
music/*.mp3

The quotes in the last command turn off wildcard expansion.

Question 9 · Write the command

Search all files in the current folder and its subfolders for the word invoice, ignoring upper/lower case and showing line numbers.

Suggested answer 
grep -r -i -n invoice .

(grep -rin invoice . is the same thing, with the options combined.)

Question 10 · Write the command

Give two different commands that count the lines in sales.csv.

Suggested answer 
wc -l sales.csv
cat sales.csv | wc -l

The first gives the file name to wc directly; the second pipes the file’s contents into wc. (The second prints only the number.)

Question 11 · Write the command

Write a command that finds all .jpg files in the current folder and all of its subfolders.

Suggested answer 
find . -name "*.jpg"

The quotes make sure find, not the shell, handles the *.

Question 12 · Write the command

Save every line of meeting-notes.txt that contains Action into a new file action-items.txt, then display the new file.

Suggested answer 
grep Action meeting-notes.txt > action-items.txt
cat action-items.txt

Question 13 · Write the pattern

A folder contains song1.mp3, song2.mp3, and song3.mp3. Write an ls command whose pattern matches song1.mp3 and song2.mp3, but not song3.mp3.

Suggested answer 
ls song[12].mp3

[12] matches exactly one character that is either 1 or 2. (song?.mp3 would also match song3.mp3.)

Question 14 · Predict the output

A folder contains no PDF files. What happens when you run ls *.pdf on a Mac (zsh), and in Git Bash?

Suggested answer
  • Mac (zsh): zsh: no matches found: *.pdf. zsh stops and doesn’t run ls at all.
  • Git Bash: Bash passes the unmatched pattern unchanged, so ls looks for a file literally named *.pdf and reports ls: cannot access '*.pdf': No such file or directory.

Hard

Question 15 · Find the bug

Sam wanted to delete his backup files and typed rm * .bak (with a space before .bak). What does this command do in Git Bash? What did he mean to type, and what should he have done first?

Suggested answer

Because of the space, * and .bak are two separate words. * matches every (non-hidden) file in the folder, so rm deletes them all, and then complains that there is no file named .bak. There is no undo. He meant rm *.bak. He should first have run ls *.bak to preview exactly which files match. (zsh on a Mac would have asked for confirmation because of the lone *, but Bash does not.)

Question 16 · Scenario

In bash-tutorial-files, Maria forgets the quotes and types find . -name *.txt. It prints only ./README.txt, even though the documents subfolders contain several more .txt files. Explain why.

Suggested answer

Without quotes, the shell expands *.txt before find runs, using the files in the current folder. The only match there is README.txt, so the command that actually runs is find . -name README.txt, which finds only files named exactly README.txt. With quotes, find . -name "*.txt", the pattern reaches find unchanged, and find applies it in every subfolder. (In a folder with several .txt files, the unquoted version fails with an error instead.)

Question 17 · Long answer

Using the data.csv file from this page, explain what each part of this pipeline does and what it prints:

sort -t, -k2 -n data.csv | tail -n 1
Suggested answer
  • sort -t, -k2 -n data.csv sorts the lines using the comma as the separator between columns (-t,), by the second column (-k2), as numbers (-n), smallest first.
  • | sends that sorted list to the next command.
  • tail -n 1 keeps only the last line, which is the row with the largest number.

It prints West,750: the region with the highest sales.

Question 18 · Short answer

Why does find . -name "*report*" list ./documents/reports in addition to quarterly-report.txt? How do you list only files?

Suggested answer

find checks the names of folders as well as files, and the folder name reports contains report. Add -type f to keep only regular files: find . -name "*report*" -type f.

Question 19 · Write the command

Write one pipeline that counts how many times you have run git commit according to your shell history.

Suggested answer 
history | grep "git commit" | wc -l

history lists your past commands, grep keeps the lines containing git commit, and wc -l counts them. (In zsh on a Mac, use history 1 instead of history to include the whole history. The count may also include the pipeline itself, since it contains git commit too.)

Question 20 · Scenario

While working on Maria’s Mac, Claude Code runs this command:

grep -rn "checkout" src

What is it doing, and why is it useful for you to be able to read it?

Suggested answer

It searches every file in the src folder and its subfolders (-r) for the text checkout, and prints each matching line with its file name and line number (-n). It’s a read-only search, so it doesn’t change anything. On a Mac, Claude Code searches your project by running ordinary find and grep commands like this one; being able to read them lets you follow what it’s doing and spot a command that does something you didn’t expect.
