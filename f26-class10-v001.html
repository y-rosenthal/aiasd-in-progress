The tutorial chapters, starting with Tutorial - intro and Project Architecture, explain each piece in more depth. This page is the checklist to follow. Where it differs from those chapters, follow this page: the chapters were written for an older version of these services and are being updated.

Where to type commands: the terminal

A terminal is a window where you type commands instead of clicking. The program inside it that reads your commands is called a shell. In this course the shell is Bash: on Windows you get it with Git, as Git Bash. Macs use zsh by default, which works the same as Bash for every command on this page. (More in Getting Bash on Your Computer (Mac and Windows).)

How to read this page:

  • A gray box with a copy button in its top right corner is a command, for example:

    node --version

    Click into a terminal, type the command (or copy and paste it), and press Enter. Then wait until the prompt (the line ending in % or $) comes back before you type the next command.

  • The boxes under The prompt to start with are not commands. You paste them into Claude’s chat box.

  • Lines that start with /, such as /model sonnet, are Claude Code commands. Type them in Claude’s chat box too, not in the terminal.

  • When a step says “Claude runs” a command, Claude types it in the terminal for you after asking your permission. You don’t type it.

  • Ctrl+C in a terminal stops the command that is running (for example the app’s server). It’s Ctrl+C on every computer, including Macs.

  • If Claude is running in a terminal window, that window is busy with Claude. To type a command yourself, open a second terminal (a new window or tab), or ask Claude to run the command for you.

  • Commands for the app itself (from Step B5 on) must run in the app’s folder, taskApp-2026. The prompt shows which folder you’re in. If it doesn’t end in taskApp-2026, type this first:

    cd ~/projects/full-stack-demo-app/taskApp-2026

    cd means “change directory”: go into a folder. After cd, the following commands run in that folder.

Reading a command

Don’t just copy commands: on this page each one is explained piece by piece, so you know what you’re asking your computer to do. Every command has the same parts. Take this one, from Step 0:

mkdir -p ~/projects/full-stack-demo-app
  • The first word is the command, the program to run. mkdir is short for “make directory” (a directory is a folder).
  • Words that start with - or -- are options: they change how the command works. -p tells mkdir to also make any missing folders on the way (here, projects), and not to complain if the folder already exists.
  • The rest are arguments: what the command works on. Here, the folder to make.
  • Spaces separate the pieces. That’s why our folder and file names have no spaces in them.
  • ~ means your home folder: /Users/maria on Maria’s Mac, /c/Users/sam in Sam’s Git Bash on Windows, and /home/ followed by your user name on Linux.
  • / separates folder names. ~/projects/full-stack-demo-app means the folder full-stack-demo-app, inside projects, inside your home folder. That is a path: directions to a folder or file.
  • Capital letters matter. taskApp-2026 and taskapp-2026 are different names.

Tip: type the first few letters of a folder or file name and press Tab. The shell finishes the name for you, with no typos.

Using Claude Code without running out of usage

As of Oct 13, 2026 · Official docs: Manage costs effectively · Model configuration · Claude Fable models on your plan

The Pro plan has a usage limit that resets every five hours, plus a weekly limit. This project takes many steps, so spend your usage wisely:

  • Use Sonnet. On Pro, Claude Code’s default model is Opus 5.5, which uses up your limit faster. Type /model sonnet at the start of each session. Sonnet 5.5 handles every step of this project.
  • Switch to Opus only when you’re stuck. If Sonnet fails to fix the same error twice, try /model opus for that problem, then switch back.
  • Haiku (/model haiku) is the cheapest. It’s fine for quick questions such as “what does this error mean?”
  • Never use Fable on the Pro plan. Fable isn’t included in Pro; it is billed separately as extra usage. Don’t turn on extra usage (usage credits).
  • Keep effort at medium (the default). Check it with /effort.
  • Check your usage with /usage. It shows how much of your five-hour and weekly limits you’ve used and when they reset.
  • Start fresh between big steps. /clear empties the conversation, so Claude doesn’t re-read a long history with every message. Your progress is safe in checklist.md (see the prompt below).
  • Don’t paste huge error logs. Paste the last 20 or so lines, or tell Claude to look at the terminal output itself.
  • Read before you approve. When Claude asks permission to run a command, read what it is about to do (Permissions, Modes, and Safety).

Step A: Install the tools

You should already have a GitHub account, Git and Claude Code from earlier classes. If not, open the boxes below. Node.js and VS Code are probably new.

A1. GitHub account (you should have this already)

Go to github.com and click Sign up. Use an email address you check. See Putting Your Repository on GitHub.

A2. Git and a Bash terminal (you should have these already)

Open a terminal (see Where to type commands), type this command, and press Enter:

git --version

git is the program, and the option --version asks it to print its version number and stop. Most programs understand --version, so it’s a quick way to check whether a program is installed. If you see a version number (such as git version 2.47.1), you’re set. If not:

  • Mac
  • Windows (Git Bash)
  • Linux

The Terminal app is already on your Mac. When you run git --version without Git, macOS offers to install the Command Line Tools, which include Git. Click Install, wait, and run git --version again.

Download and install Git for Windows from gitforwindows.org. It also installs Git Bash, the terminal we use.

Install Git with your system’s package manager. On Ubuntu or Debian, type this in the Terminal app (it asks for your password):

sudo apt install git

sudo runs the command as the computer’s administrator (that’s why it asks for your password). apt is the program that installs software on Ubuntu and Debian, install tells it what to do, and git is what to install.

Details, including the Git settings to set once, are in Installing and Configuring Git.

A3. Claude Code (you should have this already)

In a terminal, type this command and press Enter:

claude --version

claude --version asks Claude Code for its version number. If you see one, you’re set. If you get “command not found” (the shell found no program named claude), install it:

  • Mac
  • Windows (Git Bash)
  • Linux

In the Terminal app, type:

curl -fsSL https://claude.ai/install.sh | bash

What the pieces mean:

  • curl downloads whatever is at a web address.
  • -fsSL is four options run together: -f fail if the download fails, -s silent (no progress bar), -S but still show errors, -L follow the address if the website redirects it.
  • https://claude.ai/install.sh is the address of Anthropic’s install script, a small program written in Bash.
  • | (the pipe) passes what curl downloaded straight to the next command, instead of showing it on the screen.
  • bash runs it. So: “download the installer and run it”.

This is the one command on this page that does not go in Git Bash. Open PowerShell (Start menu, type PowerShell, press Enter) and type:

irm https://claude.ai/install.ps1 | iex

This is the PowerShell version of the Mac and Linux command: irm (short for Invoke-RestMethod) downloads the installer from the web address, the pipe | passes it on, and iex (Invoke-Expression) runs it.

In the Terminal app, type:

curl -fsSL https://claude.ai/install.sh | bash

curl downloads the installer from the web address (-fsSL makes it quiet, stop on errors, and follow redirects), the pipe | passes it on, and bash runs it. So: “download the installer and run it”. (The Mac tab explains each piece.)

Then close the terminal, open a new one, and type claude. Sign in with your Claude Pro account, not with an API key. Details and troubleshooting: Installing Claude Code.

If it prints v20 or a higher number (such as v24.10.0), skip to Step A5. If it prints “command not found”, or a lower number, install Node.js from its download page. Choose the LTS version (long-term support, the stable one):

  • Mac
  • Windows (Git Bash)
  • Linux

Here cd gets just the folder’s name, not a full path starting with ~: the shell looks for taskApp-2026 inside the folder you’re already in. On Windows, check that the terminal panel says bash at the right (Step A5). Then type this command and press Enter:

npm install

npm install reads the file package.json, the app’s list of the packages it needs, and downloads every one of them (and the packages they need) into a folder named node_modules. The file package-lock.json records the exact version of each package, so everyone who installs gets the same versions. It takes a minute or two. Warnings about “deprecated” packages and “vulnerabilities” are normal. Don’t run npm audit fix --force: it upgrades packages to versions this code doesn’t work with. More in Step 2: Installing the Node.js packages with npm.

Then update one package, the Supabase CLI (used from Step C on). In the same terminal, type:

npm install -D supabase@latest

What the pieces mean:

  • npm install installs a package, this time just one.
  • -D saves it as a development dependency: a tool you use while building the app, not part of the app itself. (It’s short for --save-dev.)
  • supabase@latest is the package’s name, supabase, and @latest asks for its newest version. npm updates package.json and package-lock.json to match.

Why: the project pins an early-2025 version of the CLI that can deploy Edge Functions only with Docker, and that may not work with new Supabase projects. Current versions deploy without Docker.

Step E: OpenAI API key, with a $5 limit

The app sends each new task’s title to OpenAI and gets back a label such as “work” or “shopping”. It uses a small, cheap model (gpt-4o-mini): one label costs a tiny fraction of a cent, so $5 lasts far longer than this course. The steps below make sure you can’t spend more than that.

  1. Sign up at platform.openai.com (this is the API platform; a ChatGPT subscription does not include API use). Creating your first API key requires a phone number that can receive a text message.
  2. Buy $5 of credit. Click the gear icon (Settings), open Billing, click Add payment details, and change the amount to $5 (the minimum; the default is $10). Before you confirm, turn off “Use auto-reload”, which starts out on. With auto-reload off, OpenAI never charges your card again on its own, and when the credit is used up, requests stop working.
  3. Create a project named task-app from the project menu at the top left.
  4. Set a hard spend limit. In the project’s settings, go to Limits > Spend > Edit spend limit, enter a monthly limit of 5, turn on Enforce a hard limit, and save. With the hard limit on, OpenAI refuses the project’s requests once it reaches the limit (there can be a small delay). OpenAI also emails you when spending reaches the limit.
  5. Create an API key inside the project: API keys > Create new secret key. Copy it into the worksheet immediately; OpenAI shows it only once.
  6. Give the key to your Edge Functions yourself, so the key never goes into Claude’s chat: copy the npx supabase secrets set OPENAI_API_KEY=... line from the worksheet’s Commands sheet, paste it into VS Code’s terminal (in the taskApp-2026 folder), and press Enter. What the pieces mean:
    • npx supabase runs the Supabase CLI, as in Step C.
    • secrets set stores a secret, a named value that your Edge Functions can read on Supabase’s servers but that never appears in your code or on GitHub.
    • OPENAI_API_KEY=sk-proj-... is the secret’s name, then =, then its value: your key. There are no spaces around the =. The function’s code reads the key by this name.

Step H: Deploy the Edge Functions and the Stripe webhook

  1. Claude deploys the three functions by running these commands in the terminal for you (you don’t type them). The folder names use hyphens (the older chapter, Step 11, gets them wrong):

    npx supabase functions deploy create-stripe-session

If the AI label or the upgrade fails

This code was written in early 2025, when Supabase projects used the older anon and service_role keys and an older login-token format. New projects use publishable and secret keys and a newer token format, and may not have the older keys. If creating a task or upgrading fails, open the function’s logs in the Supabase dashboard (Edge Functions) and show Claude what they say. Two known fixes, which Claude can make with you:

  • An “Invalid JWT” (401) error: turn off Verify JWT with legacy secret for that function (Edge Functions > the function > Details). This is safe here: the functions check the user’s login themselves.
  • The functions read SUPABASE_ANON_KEY or SUPABASE_SERVICE_ROLE_KEY, which are empty in projects without the older keys. The fix is to read the new keys (SUPABASE_PUBLISHABLE_KEYS and SUPABASE_SECRET_KEYS) instead, as described in Supabase’s guide to the new API keys, and deploy the functions again.

Where Docker fits

You don’t need Docker for this project, but you’ll hear about it.

Deeper dive: Docker, and running Supabase on your own computer

Docker packages a program together with everything it needs (the right versions of its language, libraries and settings) into a container that runs the same way on any computer. A container image is the packaged program; a container is a running copy of it (Hosting and Deployment introduces the idea).

In this project, everything that runs on a server runs on someone else’s computers: Supabase hosts the database and Edge Functions, and Vercel hosts the website. That is why you don’t need Docker.

Professional teams often also run a complete copy of Supabase on their own laptops, to experiment without touching the real project. The Supabase CLI does this with npx supabase start, which downloads Supabase’s container images and runs them in Docker: a local database, local logins, local storage, and a local dashboard at http://localhost:54323. To try it:

  • Mac
  • Windows (Git Bash)
  • Linux

Install Docker Desktop for Mac from docker.com and start it.

Install Docker Desktop for Windows from docker.com and start it. It may ask you to turn on WSL 2, a Windows feature it needs.

Install Docker Engine with your system’s package manager (see docs.docker.com), or Docker Desktop for Linux.

Then type npx supabase start in VS Code’s terminal, in the taskApp-2026 folder (start starts the local copy of Supabase; npx supabase stop stops it). Docker needs a fairly recent computer and several GB of disk space, which is why it isn’t required in this course. Docker Desktop is free for personal and educational use.
