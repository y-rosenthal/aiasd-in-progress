Architecture of basic static website

  • Contains only html, css and javascript (js) code. These are 3 different programming languages

    Read it in the book
    • Ch. 35 HTML, CSS, JavaScript, and Browser Developer Tools › Three languages, three jobs
    • Ch. 93 Overview of HTML, CSS, JavaScript (the whole chapter)

  • html: responsible for the basic text and basic structure of the webpage (headings, paragraphs, tables, bullet lists, numbered lists, links to other websites and pages, etc)

  • css: responsible for the look and feel of the page - e.g. colors, fonts, some positioning of info

  • javascript: language responsible for a lot of the “interactivity” that happens on a website - e.g. hovering a mouse over something changes what is seen, clicking on things and what happens, etc

  • These are not iron clad rules - e.g. HTML can also define some “look and feel” and javascript can also be used for creating text - the classifications above are the basic ideas - the details are a lot more involved

  • You can store html in .html files, css in .css files and javascript in .js files. Alternatively you can mix all 3 languages into a single (or multiple) .html file - similar to how a single MS Word document can contain English, Chinese and Hebrew all in one file.

    Read it in the book
    • Ch. 35 HTML, CSS, JavaScript, and Browser Developer Tools › A tiny website in three files

  • We looked at the basic structure of HTML, CSS and Javascript code - html has many <start> and </end> tags, css has “rules”, Javascript looks more like a typical programming language with functions, if/else, loops, etc. We didn’t go into detail but just wanted to get familiar with what each language typically looks like.

  • To view a website or a webpage, the browser is given HTML/CSS/Javascript code. These languages together explain to the browser how the page should look and act.

    Read it in the book
    • Ch. 33 Browsers, Web Servers, and HTTP › Clients and servers
    • Ch. 33 Browsers, Web Servers, and HTTP › HTTP: how browsers and servers talk

  • The html/css/javascript code for a webpage can be viewed by right clicking on a blank area of the page and choosing “view source” (or similar - browsers may differ on the exact words but this is typical). This will then open a file that contains the underlying html/css/javascript that is used by the browser to know how to show the resulting page.

    Read it in the book
    • Ch. 35 HTML, CSS, JavaScript, and Browser Developer Tools › View Source vs. Inspect
    • Ch. 35 HTML, CSS, JavaScript, and Browser Developer Tools › Opening the developer tools

  • A website starts with a “main” html file - often this is named index.html, but it doesn’t have to be.

  • If the code for a static website is on your computer you can open it by just double clicking on the .html file - it should open in a browser

  • To get the static website onto the Internet, you need to upload your code (html,css,javascript files) to a “server” computer that is running a “web server program” that is setup to host your website.

Using the “command line”

  • CLI - command line interpreter - an alternative way to control all aspects of your computer instead of clicking/dragging/etc -

  • GUI - graphical user interface - the classic way that most people control a computer by interacting with “graphical user interface” items such as icons, windows, etc by clicking/dragging/etc

    Read it in the book
    • Ch. 13 What Is the Command Line? › Two ways to talk to a computer: GUI and CLI

  • Using a CLI requires use of a “terminal” program that allows special commands (CLI commands) to be typed in to accomplish things that you could do in other ways, e.g. the following command is a “Bash” command to move the file “todo.txt” from Joe’s finance folder to his personal folder: mv /Users/joe/finance/todo.txt /Users/joe/personal

    • mv stands for the “move” command - to move files from place to place
    • /Users/joe/finance/todo.txt - is the full path including all folders from the top of the hard drive to the file named “todo.txt”
    • /Users/joe/personal - is the name of the folder that the file will be moved to
    Read it in the book
    • Ch. 13 What Is the Command Line? › Terminal vs. shell
    • Ch. 13 What Is the Command Line? › Anatomy of a command

  • there are many many different commands to do all sorts of things on the computer

  • Different computers might use different CLI languages. Probably the most popular CLI language is called Bash. It is available on Mac, Linux and can be installed on Windows (using Git Bash - you can download this for free - we used Git Bash in class - or using Windows WSL2 - we did not cover WSL2).

    Read it in the book
    • Ch. 14 Getting Bash on Your Computer (Mac and Windows) (the whole chapter)

  • Windows also has 2 other CLI languages that can be used without installing anything new - PowerShell (the newer more powerful CLI language) and CMD (the original, easier to use for simple things, but less powerful CLI language for Windows). Bash, PowerShell and CMD can all be used to accomplish the same things but with different commands.

  • We went through many of the basic Bash commands for working with files and folders

  • see the website for the bash commands we covered.

    Read it in the book
    • Ch. 15 Files, Folders, and Paths (the whole chapter)

  • Using the command line is easy for Claude Code (and other ai coding tools). It allows the coding tool to control your computer through code - which is just text - which the LLM knows very well. Controlling your computer through the Graphical User Interface (GUI) that humans usually use is harder - uses more tokens - GUI control has recently become possible but it usually requires more tokens than the equivalent accomplished by using a CLI.

deterministic vs non-deterministic

  • we defined deterministic vs non-deterministic - deterministic = always get the same results when doing the same thing, non-deterministic = results aren’t always the same when doing the same thing - results depend on probability

  • classical programming is usually deterministic

  • AI’s are non-deterministic

    Read it in the book
    • Ch. 8 How Large Language Models Work › Programming vs. training
    • Ch. 8 How Large Language Models Work › Choosing the next token

  • It is often better to have claude code do something by writing and running a program to do something than to reply based on its raw training

  • we gave the example that early LLM models had a hard time doing “exact arithmetic” with big numbers, e.g. add 24239412094823094813209413209480213480123840238402398402824242 + 43528957239578394225789324753894259834275239480587923487954238975487958791879. For smaller numbers the training set would have covered many many examples, but for larger numbers the exact example probably never appeared in the training of the AI model. However, if you ask the model to write a python program to add those same numbers, the model will be able to do that much easier. Another example from earlier models would be that when asked how many i’s there are in “mississippi” the early models would get it wrong since it was relying on its “memory” that it got from training. However, if you asked the model to write a program to figure out how many i’s there are in “mississippi” it would get the right answer. Newer models are smarter and don’t make the same mistakes because (a) they have more training (b) their harnesses often behind the scenes do things with code automatically

    Read it in the book
    • Ch. 8 How Large Language Models Work › Why LLMs sometimes make things up

  • model builders - especially anthropic and google - have been focusing on getting AIs to be good at coding - why? - if you can write a program to do something then you can do anything that a program can do - this allows AIs to extend their capabilities by writing code and eventually being able to do things that they couldn’t do before - including recursive self improvement (RSI) - see below

overview of LLMs, how they work

  • predicts next word in sequence of words

    • gave examples of :
      • “the boy went to the _______”
        • asked class for suggestions to fill in the blank and approximate order of probabilities
        • “store”, “school”, “beach”
        • asked if “purple” could be an option - yes - e.g. “purple room”
      • changing the context changes the probabilities - e.g. “his friend told him about the clowns so , the boy went to the _______” - now the most probable word is likely “circus”

  • different probabilities among all words in the English language, keeping in mind the number of words in English, each one has a very very low probability - all probs must add to 1 - still there is a most likely probability.

  • model chooses from this “probability distribution” - i.e. the “most probable word” might NOT be chosen - just like the most probable roll of two dice is 7 but other rolls are also possible, with less chance of it occurring

  • “temperature” of a model - typically a number between 0 and 1 - the amount that the model strictly adheres to the probability distribution vs focusing on the more probable words - a temperature of 0 would cause the model to always pick the most probable next word, a temp of 1 would have the model strictly pick based on the learned probability distribution

    Read it in the book
    • Ch. 8 How Large Language Models Work › An LLM predicts the next token
    • Ch. 8 How Large Language Models Work › Choosing the next token

Training models

  • models are “trained” by reading tons and tons of text - many people describe it as “reading the whole internet” - not exactly , but not far from the truth. They derive the probabilities of “next words” based on seeing tons of text and how the words appear in context. In this way they pick up the gist of how English works.

  • They “read through” all of this text many, many, many times, similar to the way a student might read their notes many times while studying for a test

  • Each time the model reads some text they try to predict the next word before reading it. If they predicted correctly - great - otherwise they try to “tweak” their internal workings so that they are very very slightly more likely to predict the right word the next time.

  • The models read through this training data many many many times. Each time they predict wrong, they “tweak” the probabilities a little and nudge the model’s predictive abilities in the right direction.

  • Training these models roughly amounts to the models reading “the entire Internet” many many many times. The computing infrastructure to accomplish this costs a LOT of money to run.

    Read it in the book
    • Ch. 8 How Large Language Models Work › How an LLM is trained
    • Ch. 8 How Large Language Models Work › Pre-training

Tokens

  • a token is a commonly occurring set of symbols in the underlying training data

  • there are a specific number of tokens in a model’s “vocabulary”

  • tokens are usually the most common sequence of symbols (letters, spaces, special characters, digits, etc)

  • some words might be comprised of a single token, some words might be made up of more than one token, some tokens are just one letter or symbol, some tokens could be part of a word e.g. “’s” apostrophe-s, some words might be made up of several tokens e.g. dictionary might be made up of three tokens dict-ion-ary

  • LLM models don’t actually generate the next word after a sequence of words, rather they generate the next “token” after a sequence of tokens

  • all models work with a specific set of tokens (the “token set” for the model), different models might use different sets of tokens in their training

  • a tokenizer is a piece of software that splits up text into the underlying tokens, e.g. a tokenizer program might convert the following text: “Dinosaurs were dangerous!” into the following tokens (the dashes - here are meant to show where one token ends and the next one starts) “Dino-saur-s- -we-re- d-anger-ous-!”

  • the most capable models today have token vocabularies that are much larger than earlier models - frontier models today can have on the order of 200k tokens in their vocabulary. Smaller models might use token vocabularies of ~50k tokens.

E.g. you might have an accountant agent, a ceo agent, a marketing agent, a customer service agent, etc. all of whom can work together on a single problem that you propose relating to your business. The agents can discuss things amongst themselves, each bringing a certain perspective to the problem and together get the work done - similar to what happens with people.

Running models

  • frontier models - the largest most capable models - these are tremendously expensive (a) to train and (b) to run. They require tremendously expensive hardware - beyond the scale of what can be run “at home” and energy costs for running the hardware is prohibitively expensive
  • much smaller models can be run on a laptop
  • tradeoffs of running “local” models on your own hardware :
    • important when privacy is a concern (e.g. working with financial data, proprietary data, working with patient data, working with student data, etc) - if you use a “hosted model” by one of the AI companies you are sending them your data - running a “local” model on your own hardware avoids sending your data to a 3rd party
    • they are slower and less capable than frontier models but are often

Overview of markdown

  • what is markdown - a humanly readable “plain text” file that has notation for “markup” such as headings, bullets, bold, italics, etc. e.g.

    • # first level heading
    • ## 2nd level heading
    • ### etc ... (up to 6th level headings)
    • Markup for *italics* for **bold text** for ***italics and bold***
    • see this reference for markdown notation for the following that we covered https://www.markdownguide.org/basic-syntax/
      • headings (see examples above)
      • bold/italics/bold-italics (see example above)
      • numbered lists / bullet lists
      • links to other documents
      • links to images

  • used by LLMs a LOT - it’s easy to process by the LLM since a markdown file is just “regular text”. Other types of non-text files are not processed directly by the LLM, e.g. Microsoft Word can contain pictures, colors, etc, same with Excel (contains colors, graphs, charts, etc) or any program that contains anything other than just plain text (i.e. the characters that you can type on your keyboard)
