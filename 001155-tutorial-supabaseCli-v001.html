79  79. Step 5a: Supabase CLI command

As of Oct 22, 2026 · Official docs: Supabase CLI

The supabase CLI is a command that you can run from your terminal to control and configure your Supabase server. The name of the command is appropriately “supabase”.

While, you can configure and manage your remote supabase server directly from the supabase website, it is often easier to use the supabase CLI command to perform much of the configuration and management of the supabase server.

Do not confuse the supabase CLI command with the supabase server. These are different products. Both can be installed locally.

  • The supabase server can be installed locally or used only remotely. In this tutorial we will NOT install the supabase server locally and only use a remote supabase server (this is much easier for beginners).

  • We WILL install the supabase CLI tool to enable us to configure and manage our remote supabase server by running commands in our terminal on our local computer.

79.1 Installing the Supabase CLI

There is more than one way to install the supabase CLI:

In the previous section you setup a Supabase project on the Supabase website. Supabase has many different features (database, authentication, edge functions, storage buckets, etc). You can configure most of what you need to configure by “clicking around” on the website. However, there are some things that cannot be done on the website. For these things we must use the “supabase CLI tool”.

In addition, using the supabase CLI command can often be easier and more efficient than accessing the same functionality via the Supabase website.

79.2 Using Supabase CLI via npx

There are different options for installing/running the supabase CLI command. The simplest and easiest way to use the supabase command is to use the npx command to run the supabase command. npx comes with Node.js. While the npm (Node Package Manager) tool is used to download and install packages, npx runs a command that comes from an npm package. This project’s package.json lists the Supabase CLI as a development dependency, so npm install has already put a copy of it in the project’s node_modules folder, and npx supabase runs that copy.

Run it in the project folder. npx looks for the program in the node_modules folder of the folder you’re in. In another folder it finds no copy and uses (or downloads) a different, often older, one. The Supabase CLI also reads which Supabase project to work on from the folder you’re in (supabase/.temp/project-ref, written by npx supabase link), so a command run in the wrong folder can change the wrong project. Signs that you’re not in the project folder: npx asks “Need to install the following packages: supabase… Ok to proceed?” (answer n), the CLI says “Cannot find project ref. Have you run supabase link?”, or it says “A new version of Supabase CLI is available” (an older copy from elsewhere ran).

For example, if you run the following command from the top level folder of your project, you will see a quite lengthy message that describes the different options you can use with the Supabase CLI tool. We will be covering some of the many options as we progress through this tutorial.

npx supabase --help

79.3 Installing Supabase CLI on your computer

NOTE: remember that the supabase CLI is NOT the same as the supabase server. In this section we are discussing installing the supabase CLI on your local computer - not the supabase server.

In this tutorial we will be using npx to run the supabase CLI. npx supabase runs the copy of the CLI in your project’s node_modules folder, the version that the project’s package.json and package-lock.json name. (If a project doesn’t include the CLI, npx downloads it first.)

The course’s copy of the project (y-rosenthal/yr-2026-full-stack-demo) already names a current version of the CLI (2.121.0, as of October 2026), so the npm install you ran in Step 2 installed it. You don’t need to install or update anything. To see which version you have, type this in VS Code’s terminal, in the task-app folder:

npx supabase --version

If it shows 2.1.1, your fork is older than that update (or you cloned the video’s original repository). Update the CLI to the newest version:

npm install -D supabase@latest

-D (short for --save-dev) records the CLI in package.json as a development dependency, and @latest asks for the newest version. The command changes package.json and package-lock.json, which you commit with your other changes later. The update matters because version 2.1.1 can prepare (bundle) Edge Functions for upload only with Docker, while current versions can do that on Supabase’s servers, so you don’t need Docker (see Where Docker fits below).

Some people prefer to install the supabase CLI on their computer instead, so that it works in every folder. You can do so by using one of the options listed below. Note that if you do install supabase on your computer then the command would simply be

  • supabase ...(other options)...

instead of

  • npx supabase ...(other options)....

See official instructions for how to install here: https://supabase.com/docs/guides/local-development/cli/getting-started The following summarizes your options to install locally:

  • Install the supabase CLI command as an npm package. To do so, run the following command from the root (top level folder) for your project:

    npm install supabase --save-dev

    NOTE: installing using the -g option to npm is no longer supported

  • You can also install the supabase CLI command on Mac by using the Homebrew package manager or on Windows by using the Scoop package manager. See the instructions here https://github.com/supabase/cli?tab=readme-ov-file to learn more about this option.

  • You can also download the actual program files from here: https://github.com/supabase/cli/releases. Be aware that this page lists “pre-release” versions as well as “release” versions. The newest regular release is marked Latest. The “pre-release” versions may have the latest fixes and modifications, but they are not supported and may not have been fully tested.

79.4 How to use the supabase command via npm and npx

IMPORTANT: If you are using supabase cli via npm then you should prefix all uses of the supabase command with “npx” (see examples below). For example, the following command will show you which version of the supabase cli you are using:

npx supabase --version

The following gives you a very short summary for how to use the supabase command

npx supabase --help

npx runs (executes) a command that comes from an npm package.

79.4.1 supabase ‘sub-commands’

The supabase command has numerous “sub commands”. For example:

  • npx supabase db is used to work with the Supabase database.
    Run npx supabase db --help to get help specific to the db sub-command.

  • npx supabase functions is used to work with Supabase “edge functions”.
    Run npx supabase functions --help to get help specific to the functions sub-command.

  • etc.

The full official reference for how to use the supabase CLI command is here: https://supabase.com/docs/reference/cli/introduction There are many options and the official reference can be overwhelming. We will walk you through an introduction of using the supabase CLI command in this tutorial.

79.5 Log in to Supabase

The login asks you questions in the terminal. Claude Code can’t answer those, so type this command yourself, in VS Code’s terminal, in the task-app folder:

npx supabase login

  • You should see the following: Hello from Supabase! Press Enter to open browser and login automatically.

  • Press Enter. If no browser opens, hold Ctrl (Cmd on a Mac) and click the login link that the terminal prints.

  • The browser page shows a verification code. Click Copy code.

  • Go back to the terminal, paste the code, and press Enter.

  • The terminal says “You are now logged in.”

The CLI then keeps a token (a long secret string, like a pass) on your computer, so you stay logged in.

79.7 Find your project’s reference ID

In the next step we will “link” the project on your computer to your Supabase project that you setup on the Supabase website. To do so, you will need to know your “project ref”. It is listed in the output of the npx supabase projects list command (see above). For example, the REFERENCE ID for the 2nd project listed above is bvysrsysihcpsomfkyja.

If you recorded it in your setup worksheet in Step 5, copy it from there: it is the part of your project URL before .supabase.co.

The project reference ID is also part of the web address of your project’s Supabase dashboard. You can find it in the address bar while you are in your project’s dashboard. It looks something like this: https://supabase.com/dashboard/project/bvysrsysihcpsomfkyja The part after /project/ is your project ref, ie. in the example above this would be bvysrsysihcpsomfkyja. However, your own project-ref will obviously be different.

79.7.1 Link your project

Once you have identified your project ref, go to the task-app folder in VS Code’s terminal (or let Claude Code run the command for you). Then run the following command, where “YOUR_PROJECT_REF” is replaced with your actual project ref (the worksheet’s Commands sheet has this line with your ref in it). This command creates a connection between your local machine and your cloud project so that future commands from the CLI know which project you’re working with. The CLI remembers the link in the folder supabase/.temp, which Git ignores.

npx supabase link --project-ref YOUR_PROJECT_REF

The option --project-ref names the project, followed by your ref. If the command asks for the database password, type the command yourself and paste the password from your worksheet.

For example, given the example above the command would be: The output shown below is what I got when I ran the command. This indicates that my project is linked with the remote supabase server. The WARNING that you see is harmless. Click on the link below to understand more about this warning message.

npx supabase link --project-ref bvysrsysihcpsomfkyja
Initialising login role...
Connecting to remote database...
Finished supabase link.
WARNING: Local database version differs from the linked project.
Update your supabase/config.toml to fix it:
[db]
major_version = 17
Explanation of the WARNING message

Developers often run a local version of the Supabase server that allows them to develop their project without having Internet access. When the developer wants to synchronize the work that they did on their local computer with the remote Supabase server, they can link their project to the remote project (as we did here) and then run the command npx supabase db push to “push” their work to the remote server. For this to work correctly, the supabase version that is installed locally must be compatible with the supabase version on the remote server.

We decided that for simplicity, we will not use a local installation of the Supabase server. However, when this git repo was originally developed, the developer did have a local Supabase server installed on his computer. The file config.toml that is in the supabase folder stores configuration information for the local Supabase server. When this project was originally developed, the supabase/config.toml file got committed to git.

The warning message is simply saying that the recorded version of the local Supabase server is not compatible with the version for remote Supabase server. However, as we said above, we are not using an actual local Supabase server. Therefore we can ignore this message. Alternatively, we can change the contents of the supabase/config.toml file by modifying the lines in the supabase/config.toml that record the local supabase version to read as follows:

[db]
major_version = 17

79.7.2 Test the link

You can run the following commands to test that your link has been established correctly.

The following should show all Supabase projects your CLI account has access to:

npx supabase projects list

In its output, the LINKED column marks the project that the current folder is linked to.

79.8 Two README commands to skip

The project’s README.md (and the tutorial video) also show commands that you should not run in this course:

  • Skip supabase init. It creates the supabase/config.toml file for a new project. This project already has that file, so init fails. Just run login and link.
  • Don’t run npx supabase start. It runs a complete copy of Supabase on your own computer, which needs Docker. This course uses only your hosted (remote) Supabase project.

79.9 Where Docker fits

You don’t need Docker for this project, but you’ll hear about it, and AI tools sometimes suggest it.

Deeper dive: Docker, and running Supabase on your own computer

Docker packages a program together with everything it needs (the right versions of its language, libraries and settings) into a container that runs the same way on any computer. A container image is the packaged program; a container is a running copy of it (Hosting and Deployment introduces the idea).

In this project, everything that runs on a server runs on someone else’s computers: Supabase hosts the database and Edge Functions, and Vercel hosts the website. That is why you don’t need Docker. (Old versions of the Supabase CLI, such as 2.1.1, needed Docker to prepare Edge Functions for upload; current versions don’t. See the update above.)

Professional teams often also run a complete copy of Supabase on their own laptops, to experiment without touching the real project. The Supabase CLI does this with npx supabase start, which downloads Supabase’s container images and runs them in Docker: a local database, local logins, local storage, and a local dashboard at http://localhost:54323. To try it:

  • Mac
  • Windows (Git Bash)
  • Linux

Install Docker Desktop for Mac from docker.com and start it.

Install Docker Desktop for Windows from docker.com and start it. It may ask you to turn on WSL 2, a Windows feature it needs.

Install Docker Engine with your system’s package manager (see docs.docker.com), or Docker Desktop for Linux.

Then type npx supabase start in VS Code’s terminal, in the task-app folder (start starts the local copy of Supabase; npx supabase stop stops it). Docker needs a fairly recent computer and several GB of disk space, which is why it isn’t required in this course. Docker Desktop is free for personal and educational use.

Question 1 · True or false

The Supabase CLI and the Supabase server are the same product.

Suggested answer

False. The CLI is a command (supabase) that you run in your terminal to configure and manage a Supabase project. The CLI’s GitHub releases page lists a “release” version and several newer “pre-release” versions. Which should a beginner use, and why?

Suggested answer

The latest regular release. Pre-release versions may have the newest features and fixes, but they are not supported and may not be fully tested.

Question 14 · Short answer

Claude Code can run most commands for you. Why do you type npx supabase login yourself?

Suggested answer

The login asks you questions in the terminal (press Enter to open the browser, then paste the verification code). Claude Code can’t answer those questions, so you type the command yourself in VS Code’s terminal, in the task-app folder. Claude can run npx supabase link for you, unless it asks for the database password.

Question 15 · Scenario

Sam runs npx supabase --version and it shows 2.1.1. What should he do, and why does it matter?

Suggested answer

His fork names an old CLI version. He updates it with:

npm install -D supabase@latest

-D records the CLI as a development dependency in package.json, and @latest asks for the newest version. It matters because version 2.1.1 can prepare Edge Functions for upload only with Docker, while current versions do that on Supabase’s servers, so he doesn’t need Docker. The command changes package.json and package-lock.json, which he commits later.

Question 16 · Scenario

After running npx supabase link, you see:

WARNING: Local database version differs from the linked project.
Update your supabase/config.toml to fix it:
[db]
major_version = 17

What does the warning mean, why can you ignore it in this tutorial, and how could you make it go away?

Suggested answer

The file supabase/config.toml stores settings for a local Supabase server. The original developer ran one, and the file he committed to Git records a different database version than the one your remote project uses. Because this tutorial doesn’t run a local Supabase server, the mismatch doesn’t matter. To make the warning go away, edit supabase/config.toml and set major_version = 17 in its [db] section.

Question 17 · Scenario

You run npx supabase projects list. Before the list of projects, the output says Cannot find project ref. Have you run supabase link? Is something broken? What does the message mean?

Suggested answer

Nothing is broken; the list of projects is still printed. The message means that the folder you are in is not linked to a Supabase project yet, so the CLI doesn’t know which project “this” folder belongs to. Commands that work on your project need that link. Fix it by running npx supabase link --project-ref <your-project-ref> from the project’s top-level folder.

Question 18 · Short answer

Why should you run npx supabase link from your project’s top-level folder rather than from, say, your home folder?

Suggested answer

The CLI works with the supabase folder inside your project, which holds config.toml, the database migrations and the edge functions. Linking records which online project belongs to this project folder, so later commands run from that folder (for example, pushing the database or setting secrets) know where to send their changes. From your home folder, the CLI wouldn’t find your project’s supabase folder.

Question 19 · Scenario

A teammate says: “I already ran npx supabase login, so the CLI knows which project to work on.” Is that right? Explain.

Suggested answer

Not quite. login only connects the CLI to your Supabase account, and one account can have several projects (npx supabase projects list shows them all). link is the step that tells the CLI which of those projects belongs to the current project folder. You need both.

Question 20 · Scenario

Following the project’s README, Maria runs npx supabase init, and it fails. What went wrong, and what should she do instead?

Suggested answer

Nothing is broken. init creates the supabase/config.toml file for a new project, and this project already has that file, so init fails. She skips init and just runs npx supabase login and npx supabase link --project-ref <her-project-ref>.

Question 21 · Multiple choice

Why does this course not need Docker?

  1. Docker only works on Linux
  2. Everything that runs on a server runs on someone else’s computers (Supabase and Vercel), and the current CLI prepares Edge Functions without Docker
  3. The Supabase CLI includes its own copy of Docker
  4. Docker is needed only for the front end, which runs in the browser
Suggested answer

b. Supabase hosts the database and Edge Functions, and Vercel hosts the website, so nothing needs to run in containers on your computer. Docker is needed only for running Supabase locally (npx supabase start) or with old CLI versions. Docker runs on Mac, Windows and Linux (a), the CLI doesn’t include Docker (c), and the browser doesn’t use Docker at all (d).

Question 22 · Short answer

What does npx supabase start do, and what does it need? Why might a professional team use it?

Suggested answer

It runs a complete copy of Supabase on your own computer (a local database, local logins, local storage and a local dashboard at http://localhost:54323). It downloads Supabase’s container images and runs them in Docker, so Docker must be installed and running. Teams use it to experiment without touching the real project. This course doesn’t use it.
